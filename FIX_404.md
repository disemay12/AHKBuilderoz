# 🔧 Решение проблемы 404 на GitHub Pages

## ❌ Проблема

Вы видите ошибку **"Site Not Found"** или **404** при открытии сайта на GitHub Pages.

## ✅ Решение

### Шаг 1: Узнайте имя вашего репозитория

Перейдите на страницу вашего репозитория на GitHub. Имя репозитория находится в URL:
```
https://github.com/YOUR_USERNAME/REPO_NAME
```

Например, если URL: `https://github.com/ivan/ahk-editor`
- Имя репозитория: `ahk-editor`

### Шаг 2: Обновите `vite.config.js`

Откройте файл `vite.config.js` и найдите строку:

```javascript
const repoName = 'ahk-script-editor'; // Замените на имя вашего репозитория
```

Замените `'ahk-script-editor'` на **имя вашего репозитория**:

```javascript
const repoName = 'ahk-editor'; // Ваше имя репозитория
```

### Шаг 3: Запушьте изменения

```bash
git add vite.config.js
git commit -m "Fix: correct base path for GitHub Pages"
git push
```

### Шаг 4: Дождитесь деплоя

1. Перейдите на вкладку **Actions** в вашем репозитории
2. Дождитесь завершения нового workflow (зелёная галочка ✅)
3. Обычно это занимает 1-3 минуты

### Шаг 5: Проверьте URL

Ваш сайт должен быть доступен по адресу:
```
https://YOUR_USERNAME.github.io/REPO_NAME/
```

**Важно:** URL должен заканчиваться на `/` (слеш)!

---

## 🔍 Проверка настроек GitHub Pages

### 1. Убедитесь, что GitHub Pages включен

1. Перейдите в **Settings** → **Pages**
2. В разделе **"Build and deployment"**:
   - **Source** должен быть **"GitHub Actions"**
   - НЕ должно быть выбрано "Deploy from a branch"

### 2. Проверьте статус деплоя

1. Перейдите на вкладку **Actions**
2. Найдите последний workflow run
3. Убедитесь, что он завершился успешно (зелёная галочка ✅)
4. Если есть ошибка - нажмите на него и посмотрите логи

### 3. Проверьте URL

Правильный формат URL:
```
✅ https://username.github.io/repo-name/
✅ https://username.github.io/repo-name/index.html

❌ https://username.github.io/  (без имени репозитория)
❌ https://username.github.io/repo-name  (без слеша в конце)
```

## 🛠️ Альтернативное решение: Простой base path

Если проблема сохраняется, попробуйте упрощённую конфигурацию:

### Вариант 1: Относительный путь

Откройте `vite.config.js` и измените:

```javascript
export default defineConfig({
  base: './',  // Относительный путь
  // ... остальной код
});
```

Затем запушьте изменения:
```bash
git add vite.config.js
git commit -m "Fix: use relative base path"
git push
```

### Вариант 2: Абсолютный путь с именем репозитория

```javascript
export default defineConfig({
  base: '/repo-name/',  // Замените 'repo-name' на имя вашего репозитория
  // ... остальной код
});
```

## 🚨 Если ничего не помогло

### Проверьте консоль браузера

1. Откройте ваш сайт в браузере
2. Нажмите **F12** (откроется DevTools)
3. Перейдите на вкладку **Console**
4. Посмотрите ошибки

Типичные ошибки:
- `Failed to load resource: 404` - неправильный base path
- `Uncaught SyntaxError: Unexpected token '<'` - HTML загружается вместо JS

### Проверьте Network tab

1. В DevTools перейдите на вкладку **Network**
2. Обновите страницу (F5)
3. Посмотрите, какие файлы не загружаются (статус 404)
4. Проверьте пути к файлам

### Очистите кэш браузера

Иногда браузер кэширует старую версию:
1. Нажмите **Ctrl+Shift+R** (жёсткое обновление)
2. Или очистите кэш вручную

## 💡 Быстрое решение для тестирования

Если нужно быстро проверить, что деплой работает:

1. Создайте файл `public/test.html`:
```html
<!DOCTYPE html>
<html>
<head><title>Test</title></head>
<body>
  <h1>GitHub Pages работает!</h1>
  <p>Если вы видите эту страницу, деплой успешен.</p>
</body>
</html>
```

2. Запушьте изменения:
```bash
git add public/test.html
git commit -m "Test: add test page"
git push
```

3. Откройте: `https://YOUR_USERNAME.github.io/REPO_NAME/test.html`

Если тестовая страница открывается - проблема в конфигурации Vite.
Если тестовая страница тоже 404 - проблема в настройках GitHub Pages.
